# วันที่ 11 — เปลี่ยนคำให้ใช้ได้ทุกวัย + เก็บงานค้าง 3 ข้อ

## ส่วนที่ 1 — โจทย์ (บันทึกตามที่ได้รับ)

อ่าน CLAUDE.md ก่อน แล้วทำตาม convention เดิมทั้งหมด
บันทึกข้อความนี้เป็น `docs/day11-plan.md` (ส่วนที่ 1) ก่อนเริ่มงาน
ห้ามแก้โค้ดจนกว่าจะเสนอ "ส่วนที่ 2 — แผน" แล้วคาเด็ทอนุมัติ ถ้าแผนส่งไม่ถึงให้ส่งซ้ำ
ทำงานบน branch ใหม่ `feat/day11-wording`

### เป้าหมาย
ยาตรงเป็นแอปเตือนกินยาสำหรับ **ทุกคนทุกวัยที่ต้องกินยา** (วิตามิน ยาประจำตัว ยาชั่วคราว) ไม่ใช่เฉพาะผู้ป่วย
→ เอาคำว่า "ผู้ป่วย", "ผู้ดูแล", "ญาติผู้ดูแล", "ญาติ" ออกจาก **ทุกข้อความที่ผู้ใช้เห็น**
→ ฟีเจอร์แจ้งญาติเปลี่ยนชื่อเป็น **"คนที่ห่วงใย"**

### ส่วน A — เปลี่ยนคำ

1. **ขอบเขต "ข้อความที่ผู้ใช้เห็น"** ได้แก่ ข้อความใน template, ป้ายปุ่ม, title ของหน้า, aria-label, alt, ข้อความ sr-only, snackbar/dialog, ข้อความ error จาก API ที่แสดงบนจอ, manifest (name/description), ข้อความ LINE ทั้งหมด (reply, Flex, altText, quick reply, rich menu ถ้าสร้างจากโค้ด), Web Push (title/body), หน้า welcome
2. **ห้ามเปลี่ยน:** ชื่อตาราง/คอลัมน์ DB (`caregivers`, `escalate_after_min` ฯลฯ), ชื่อ endpoint (`/api/caregivers`), ชื่อไฟล์/คลาส/ตัวแปร, ชื่อ tab Node-RED, ไฟล์ `docs/day*-plan.md` เก่า และไฟล์ใน `docs/motion/`
3. **หลักการแทนคำ** (ให้ใช้ตามบริบท ไม่ใช่ find-replace ทั้งไฟล์):
   - ผู้ป่วย → ตัดทิ้ง / "คุณ" / "ผู้ใช้" / ชื่อผู้ใช้
   - ผู้ดูแล / ญาติ / ญาติผู้ดูแล → "คนที่ห่วงใย"
   - "สำหรับผู้ป่วยและญาติผู้ดูแล" (หน้า welcome) → เสนอคำโปรยใหม่ 2–3 ตัวเลือกที่สื่อว่า "ใช้ได้ทุกวัย" ให้คาเด็ทเลือก
   - ข้อความ LINE ถึงคนที่ห่วงใย (escalation) ต้องยังเข้าใจได้ทันทีว่าใครยังไม่กินยา
4. **สิ่งที่ยังต้องคงไว้:** ข้อความ "ไม่ใช่คำแนะนำทางการแพทย์", น้ำเสียงน้องยาตรง ค่ะ/นะคะ
5. **กฎข้อความ LINE เดิม:** อิโมจิไม่เกิน 1 ตัวต่อบรรทัด, ตัวแปรที่ยาวไม่แน่นอนอยู่บรรทัดของตัวเอง, บรรทัดคงที่ไม่เกินประมาณ 22 ตัวอักษรไทย
6. **พรอมต์ Gemini** ที่มีคำว่าผู้ป่วยไม่ต้องเปลี่ยน แต่ให้ลิสต์ไว้ในแผนว่ามีที่ไหน
7. ข้อความที่อยู่ใน **LINE Official Account Manager** (ข้อความต้อนรับ, รูป rich menu ที่ไม่ได้สร้างจากโค้ด) Claude Code แก้ไม่ได้ → ลิสต์ให้คาเด็ทไปแก้เอง

### ส่วน B — งานค้าง

8. **manifest.webmanifest ขาด `start_url`** (demo-check.sh ตก 1 ข้อ): ให้สำรวจว่าควรเป็น `/` หรือ `/today` เมื่อพิจารณา rootGuard, หน้า welcome, deep link และ WebAPK ที่ติดตั้งอยู่บน S23 FE (บัญชี "การ์ตูน" ที่ถือ Web Push ห้ามหลุด) แล้วเสนอพร้อมเหตุผล
9. **README:** คำสั่ง hash รหัส Node-RED (`docker compose run --rm nodered npx node-red admin hash-pw`) ใช้ไม่ได้ เพราะเปิด Node-RED ตัวที่ 2 ที่รัน flow จริง → แก้เป็นแบบ `docker compose exec -it nodered node -e "...bcryptjs.hashSync..."` ให้รันได้จริง (ห้ามใส่รหัสจริงในตัวอย่าง)
10. **`POST /api/demo/remind-now`** ส่ง LINE อย่างเดียว ไม่ส่ง Web Push แม้ `notify_both=1` (สงสัย reminder-service.js ราว ๆ บรรทัด 183 ไม่ส่ง `opts.push`) → ให้พฤติกรรมเหมือน cron จริง พร้อมเทส

### ส่วนที่ 2 ที่ต้องเสนอ (ก่อนแก้)
11. ตารางทุกจุดที่เจอคำ (ไฟล์:บรรทัด | ข้อความเดิม | ข้อความใหม่ที่เสนอ) แยกเป็น frontend / LINE / Web Push / อื่น ๆ

13. คำถามที่ต้องให้คาเด็ทตัดสิน (คำโปรย welcome, start_url, คำที่กำกวม)

### ตอนทำ
14. ทำเป็นช่วง A (frontend) → B (LINE/Push/Node-RED) → C (งานค้าง 8–10) → รันเทส → รายงาน → commit แยกทีละช่วง
15. **ต้อง `docker compose stop nodered` ก่อนแก้ flows.json** และถามก่อน restart nodered ทุกครั้ง (ห้ามช่วง 23:50–00:15, 02:55–03:10 และ ±10 นาทีของเวลามื้อบัญชีทดสอบ)
16. เทสที่เช็กข้อความไทยให้ **แก้ค่าที่คาดหวัง ห้ามลบเทส** และจำนวนเทสต้องไม่ลด; เพิ่มเทสที่ grep ว่าไม่มีคำต้องห้ามหลุดในข้อความที่ผู้ใช้เห็น (ต้องมีตัวควบคุมบวก ระวังข้อความไทยที่ถูกเข้ารหัส \uXXXX ใน bundle)
17. รันชุดเทสเดิมทั้งหมด: test-all.sh, ng test, first-screen, overflow (ต้องมี ng serve :4200), state-check, review-e2e, scan-lazy/offline, dup-styles, welcome-overlap-check — เพราะข้อความเปลี่ยนความยาว ต้องเช็กล้นด้วย
18. ถามก่อนรันเทสที่ recreate container, ก่อน push และก่อนเปิด PR — คาเด็ท merge เอง
19. ก่อน commit: `git grep` ต้องไม่เจอชื่อจริง ชื่อ LINE หรือโดเมน ngrok; ห้าม commit ไฟล์ต้องห้ามตาม CLAUDE.md
20. รายงาน: ตารางเทสผ่าน/ไม่ผ่าน (ก่อน → หลัง), ไฟล์ที่เปลี่ยน, ภาพ after, รายการที่คาเด็ทต้องแก้เองใน LINE OA Manager

- **ข้อความต้อนรับ (Greeting message)** — ถ้ายังเปิดใช้และมีคำว่าผู้ป่วย/ญาติ/ผู้ดูแล (แนะนำปิดให้บอทตอบเองผ่าน `follow` event ที่โค้ดจัดการอยู่แล้ว เพื่อไม่ให้ซ้ำ)
- **ข้อความตอบกลับอัตโนมัติ (Auto-response messages) และข้อความ AI ตอบกลับ** ถ้าเปิดไว้
- **คำอธิบายบัญชี / Status message / โปรไฟล์ OA** (ช่อง "ข้อมูลบัญชี" ที่ผู้ใช้เห็นก่อนเพิ่มเพื่อน)
- **รูป rich menu** — ปัจจุบันสร้างจากโค้ด (`frontend/tools/make-line-richmenu.mjs` → `docs/line-richmenu/richmenu.png`, 3 ช่อง "วันนี้ / เปิดแอป / วิธีใช้") **ไม่มีคำต้องห้าม ไม่ต้องอัปโหลดใหม่** แต่ถ้าเคยอัปโหลดแบบอื่นด้วยมือใน OA Manager ให้ตรวจเอง
- **เมนูแชท Rich message / Rich video message / คูปอง / โพสต์ในไทม์ไลน์** ที่เคยสร้างมือ
- **รายการตรวจ:** `docs/line-console-checklist.md` (11 จุดมีคำ) — จะแก้ให้ในช่วง B ส่วนที่เป็นเอกสาร
