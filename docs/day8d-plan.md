### D1: ฐานของระบบดีไซน์

#### 1. ระบบขนาด ก / ก+ / ก++
- ตรวจว่าตอนนี้สลับขนาดด้วยกลไกอะไร (root font-size, class, token) แล้วเสนอวิธีที่ทุกขนาดในแอปเป็น rem จาก token เดียว
- **ขนาด ก (ค่าเริ่มต้นใหม่):** root 16px
  - ก+ ประมาณ 1.125 เท่า
  - ก++ ประมาณ 1.25 เท่า
  - ถ้ากลไกเดิมใช้ค่าอื่น ให้เสนอในแผน
- ผู้ใช้ที่เคยเลือกขนาดไว้แล้ว ต้องได้ขนาดเดิม (ไม่รีเซ็ต)
- **typography scale ที่ขนาด ก:**
  - หัวหน้า 24px / น้ำหนัก 500
  - หัวส่วน 18px / 500
  - ป้ายกลุ่ม 13px สี secondary
  - เนื้อหา 16px
  - ข้อความรอง 14px
  - ต่ำสุด 13px (ยกเว้น disclaimer 12px)
- **Mitr ใช้น้ำหนัก 500** เป็นหลัก เลิกใช้ 600/700 ยกเว้นตัวเลขใหญ่ที่ตั้งใจเน้น
- **spacing token** เป็น rem: 4, 8, 12, 16, 24, 32
  - gutter 16px
  - ระยะระหว่างส่วน 24px
- **ขนาดตัวควบคุม:**
  - ปุ่มหลัก 48px
  - ปุ่มกะทัดรัดในแถว: สูงที่มองเห็น 36px แต่พื้นที่แตะ ≥ 48px (ขยายด้วย padding หรือ ::before)
  - ช่องกรอก 48px
- **card:** radius 16px, เส้นขอบ 1px โทนอ่อน, เงาเบาหรือไม่มีเงา (ให้ดูแบนและสะอาด)

#### 2. คอมโพเนนต์พื้นฐาน (shared/ui/ แต่ละตัวมี scss ของตัวเอง)
- **yt-page-header:** หัวหน้า 1 แถว สูงประมาณ 56px มีชื่อหน้าและ action ทางขวาได้ 1 อย่าง
  - **เลิกแสดงโลโก้ใหญ่ทุกหน้าด้านใน** (โลโก้คงไว้ที่ Login/Register และ sidebar บนจอกว้าง)
- **yt-list-row:**
  - สูงขั้นต่ำ 56px, padding 12×16
  - ช่องซ้าย: ไอคอนหรือน้องยาตรง (ไม่บังคับ)
  - ช่องกลาง: หัวเรื่อง 16px/500 + บรรทัดรอง 14px
  - ช่องขวา: ป้าย, ปุ่มกะทัดรัด หรือ chevron
  - เส้นคั่นระหว่างแถว แถวที่แตะได้ต้องมีสถานะ focus/active
- **yt-section:** ป้ายกลุ่ม + การ์ดที่รวมแถวไว้ด้วยกัน
- **yt-sheet:** แผ่นล่างบนมือถือ (MatBottomSheet หรือของเดิมถ้ามี) และแผงขวาหรือ dialog บนจอกว้าง ≥ 1024px
- **yt-banner:** แถบบางบรรทัดเดียวด้านบนของเนื้อหา
  - มี 4 ชนิด: info (ฟ้า), warning (เหลือง), success (เขียว), offline
  - แสดงได้**ครั้งละ 1 แถบเท่านั้น** เรียงลำดับความสำคัญ: เชื่อมต่อหมดอายุ > ออฟไลน์ > เวอร์ชันใหม่ > ชวนติดตั้ง
- **แจ้งเวอร์ชันใหม่:** เปลี่ยนจาก snackbar มาเป็น yt-banner (เดิม snackbar บังปุ่ม "เลือกรูปจากเครื่อง" ในหน้าสแกน)
- **ชวนติดตั้ง:** บนหน้าวันนี้เหลือเป็น yt-banner บรรทัดเดียวที่ปิดได้ ส่วนคำอธิบายแบบละเอียด (รวมขั้นตอนของ iPhone) ย้ายไปหน้าตั้งค่า

#### 3. น้องยาตรง 3 ขนาด (component เดียว รับ size และ pose)
- **S 36px:** ผู้พูดในแถบข้อความ, หัวการ์ดความคืบหน้า, คำเตือน AI
- **M 56px:** Login/Register, การ์ดหลักหน้าสรุป
- **L 112px:** เฉพาะช่วงพิเศษ ได้แก่ กินครบทั้งวัน (cheer), หน้าว่าง (ยังไม่มียา), บันทึกยาใหม่สำเร็จ
- ถ้าท่าไหนย่อเป็น 36px แล้วดูไม่ออก ให้ใช้เฉพาะหน้าน้องยาตรง (แบบรูปโปรไฟล์ LINE)
- **ห้ามมีน้องยาตรงขนาด L ในจอแรกของหน้าที่ใช้งานประจำ** ยกเว้นช่วงพิเศษข้างต้น

#### 4. สีและสถานะ
- ใช้ token เดิมและ --yt-scale-* จากหน้าสรุป
- **ห้ามมีกล่องสีเหลืองซ้อนกันเกิน 1 ชั้นในหน้าเดียว**
  - ป้ายสถานะในแถวใช้ chip เล็ก
  - กล่องเตือนใหญ่ใช้เมื่อมีเรื่องเดียวที่ต้องทำเท่านั้น
- ข้อมูลทั่วไป (เช่น คำเตือนเรื่อง AI) ใช้โทนฟ้า info ไม่ใช่เหลืองหรือแดง

#### 5. เครื่องมือตรวจใหม่: tools/first-screen-check.mjs
- ใส่ data-first-screen="<ชื่อ>" ที่ element สำคัญของแต่ละหน้า (รายการอยู่ใน D2/D3)
- ตรวจที่ **375×667 และ 360×640** ขนาด ก และ ก+:
  - ขอบล่างของ element ≤ ความสูงจอ − ความสูง bottom nav − 8px
- ขนาด ก++ ยอมให้เลื่อนได้ แต่ต้องรายงานผลไว้
- **overflow-check.mjs:** เอาข้อยกเว้นแถบคำแนะนำเลื่อนแนวนอนในหน้าสแกนออก ห้ามมีเนื้อหาที่ต้องเลื่อนแนวนอนเพื่ออ่าน
- **ขนาดจอกว้าง:** เพิ่ม 1366×768 และ 1920×1080 ในการตรวจ overflow
  - ตรวจด้วยว่าการ์ดที่อยู่แถวเดียวกันสูงเท่ากัน (ต่างกันไม่เกิน 2px)

### D2: หน้าที่ใช้ทุกวัน (วันนี้, Login/Register, สแกน, Review)

#### หน้าวันนี้ (ต้องอยู่ในจอแรก: ความคืบหน้า, ปุ่มฟัง, ปุ่มกินแล้วของมื้อที่ถึงเวลาหรือเลยเวลา)
- **หัวหน้า 1 แถว:** "สวัสดี คุณ{ชื่อ}" 20px ซ้าย และวันที่แบบย่อ "อ. 13 ต.ค." 14px ขวา (ไม่มีโลโก้, ไม่มีคำทักทายตามช่วงเวลาแยกบรรทัด)
- **การ์ดความคืบหน้า** (สูงประมาณ 72–80px):
  - ซ้าย: "วันนี้กินแล้ว" + ตัวเลข "3 / 5" + แถบความคืบหน้าบาง 6px
  - ขวา: ปุ่มกะทัดรัด 🔊 "ฟัง" (อ่านยาที่ยังไม่ได้กิน)
  - น้องยาตรง S ท่าตามสถานะ
  - เลิกใช้วงแหวนใหญ่ + กล่องคำพูด + กล่องเหลือง "ยังมี n รายการ" (ข้อความซ้ำ)
- **มื้อเรียงตามลำดับความสำคัญ:**
  1. มื้อที่เลยเวลาหรือถึงเวลา: เปิดไว้
  2. มื้อถัดไป: พับไว้ แสดงชื่อยาแบบสรุปบรรทัดเดียว + "อีก n นาที"
  3. มื้อที่กินครบแล้ว: พับไว้เป็นแถวสีเขียว (แบบที่มีอยู่แล้ว)
- **หัวมื้อ:** "เช้า · 08:00" + chip สถานะ (เช่น "เลยเวลา 7 ชม.") + ปุ่มไอคอน 🔊 ฟังมื้อนี้ (พื้นที่แตะ 48px)
- **ยาแต่ละตัวเป็น yt-list-row:**
  - หัวเรื่อง: ชื่อ + ความแรง
  - บรรทัดรอง: "1 เม็ด · หลังอาหาร"
  - ขวา: ปุ่มกะทัดรัด "✓ กินแล้ว"
  - กินแล้ว: แสดง ✓ และเวลาที่กิน
- **"กินครบมื้อนี้":** ปุ่มเต็มความกว้างท้ายมื้อ เมื่อมื้อนั้นมียาที่ยังไม่กิน ≥ 2 ตัว
  - ตรวจว่ามี endpoint สำหรับบันทึกหลายตัวหรือไม่ (มี takeMany ใน dose-service อยู่แล้วสำหรับ LINE) แล้วเสนอในแผน: endpoint ใหม่ที่ใช้กติกาเจ้าของเดียวกัน (ไม่ใช่เจ้าของ = ข้าม, กดซ้ำไม่หักยาซ้ำ) พร้อมเทส หรือเรียกทีละตัว
- **ออฟไลน์:** แถบออฟไลน์เดียวด้านบนบอกเหตุผล ปุ่มกินแล้วกดไม่ได้ **ไม่ต้องมีข้อความ "ต่ออินเทอร์เน็ตก่อนนะคะ" ใต้ทุกการ์ด** ถ้าผู้ใช้แตะปุ่มที่กดไม่ได้ ให้แสดงข้อความนั้นครั้งเดียว
- **กินครบทั้งวัน:** น้องยาตรง L ท่า cheer + "วันนี้กินครบแล้ว เก่งมากเลยค่ะ"
- **ลิงก์ "7 วันล่าสุด กินครบ n% ›"** เป็นแถวเล็กท้ายหน้า
- **จอกว้าง ≥ 1024px:** มื้อเรียงเป็นคอลัมน์ (2–4 คอลัมน์ตามความกว้าง) การ์ดความคืบหน้าอยู่บนสุดเต็มความกว้าง

#### Login / Register (ต้องอยู่ในจอแรก: ทุกช่องและปุ่มยืนยัน ทั้งขนาด ก และ ก+)
- **แถวบน:** โลโก้เล็ก 28px + "ยาตรง" ซ้าย และตัวเลือก ก / ก+ / ก++ แบบกะทัดรัดขวา (สูง 32px)
- **หัวเรื่อง:** น้องยาตรง M + "ยินดีต้อนรับกลับมา" 20–22px บรรทัดเดียว + บรรทัดรอง 14px
  - เลิกใช้กล่องคำพูด "สวัสดีตอนบ่ายค่ะ" (ทักซ้ำ)
- **ช่องกรอก 48px** ป้ายชื่อเหนือช่อง 14px
- **คีย์บอร์ดบนมือถือ:** เมื่อโฟกัสช่องใด ปุ่มยืนยันต้องเลื่อนขึ้นมาให้เห็นได้
  - เสนอวิธีในแผน เช่น meta viewport interactive-widget=resizes-content สำหรับ Android และ scrollIntoView ที่รวมปุ่มสำหรับ iOS
- ท้ายหน้า: สโลแกนและ disclaimer ตามเดิม แต่เล็กลง
- Register ใช้รูปแบบเดียวกัน

#### สแกน (ต้องอยู่ในจอแรก: คำเตือน AI, คำแนะนำครบ, ปุ่มถ่ายรูป, ปุ่มเลือกรูป)
- **หัวหน้า:** ← "เพิ่มยาใหม่"
- **ขั้นตอน:** ป้ายสั้น "ถ่าย · ตรวจ · บันทึก" บรรทัดเดียว
- **แถบคำเตือน AI (info สีฟ้า) อยู่ใต้ขั้นตอน:** น้องยาตรง S เป็นผู้พูด "น้องยาตรงช่วยอ่านซองยาให้นะคะ แต่อาจอ่านผิดได้ ตรวจทุกช่องก่อนบันทึกนะคะ"
  - เลิกวางข้อความนี้ไว้ท้ายหน้า
- **ตัวสลับ** "ถ่ายรูปซองยา / พิมพ์เอง" แบบกะทัดรัด
- **กรอบถ่ายรูปเตี้ยลง** และ**ใส่คำแนะนำ 3 ข้อในกรอบ** แบบบรรทัดละข้อพร้อมไอคอน (ห้ามเลื่อนแนวนอน):
  1. วางซองบนพื้นเรียบ ให้อยู่ในกรอบ
  2. ถ่ายตรง ไม่เอียง ไม่มีเงาบัง
  3. สแกนทีละซอง · เฉพาะซองที่พิมพ์ด้วยเครื่อง
- **ปุ่ม:** "ถ่ายรูปซองยา" (หลัก 48px) และ "เลือกรูปจากเครื่อง" (รอง)
- **เอาน้องยาตรงตัวใหญ่ + กล่องคำพูดออก** (ซ้ำกับคำแนะนำ)
- **ระหว่างวิเคราะห์:** ใช้น้องยาตรง S + "กำลังอ่านซองยาอยู่นะคะ..."
- disclaimer ทางการแพทย์อยู่ท้ายหน้าได้

#### Review (ขั้นตรวจข้อมูล)
- **แถบเด่นบนสุด** (warning ถ้ามีช่องที่ติด flag, info ถ้าไม่มี) พร้อมน้องยาตรง S
  - "ตรวจทุกช่องก่อนบันทึกนะคะ" + จำนวนช่องที่ควรตรวจเป็นพิเศษ
- **ช่องที่ติด flag** มีกรอบและข้อความบอกเหตุผลอยู่ที่ช่องนั้น
- **ปุ่มบันทึกอยู่ในแถบปุ่มติดล่างจอ** (sticky action bar) เพื่อให้เห็นตลอดแม้ฟอร์มยาว
- วัดหน้าจริงแล้วเสนอขนาดในแผน (ชีฟยังไม่เห็นหน้านี้)

#### ยาของฉัน (ต้องอยู่ในจอแรก: ปุ่มเพิ่มยา และยาอย่างน้อย 3 ตัว)

### 2.1 กลไกขนาดตัวอักษรปัจจุบัน → ระบบ rem จาก token เดียว

**ปัจจุบัน**
- `FontScaleService` (`shared/font-scale.service.ts`) ตั้ง `--yt-font-scale` บน `<html>` เป็น 1 / 1.12 / 1.25 (เก็บ `localStorage['yatung_font_scale']` = 100/112/125 **เฉพาะตอนผู้ใช้กดเลือกเอง** — ค่าเริ่มต้นไม่ถูกเขียนลง storage)
- `index.html` มี inline script ตั้งค่าเดียวกันก่อนแอปโหลด (กันกระพริบ)
- `_base.scss`: `html { font-size: calc(112.5% * var(--yt-font-scale)) }` → ก = **18px**, ก+ = 20.2px, ก++ = 22.5px
- ขนาดเกือบทั้งหมดเป็น rem อยู่แล้ว แต่ยังมี **286 ค่า px ใน 34 ไฟล์ scss** (ส่วนใหญ่ border/ขนาดไอคอน/min-height) และ `--yt-tap: max(56px, 3.25rem)` กับ Material override `*-container-height: var(--yt-tap)`

**ข้อเสนอ**
1. `html { font-size: calc(100% * var(--yt-font-scale)) }` (ก = 16px) และสเกลเป็น **1 / 1.125 / 1.25** (ก+ = 18px, ก++ = 20px) — token เดียวคือ `--yt-font-scale`; ทุกขนาดในแอปเป็น rem จาก token ใน `_tokens.scss`
2. ตรวจ px ทั้ง 286 จุด แยกเป็น (ก) เส้นขอบ/เงา 1–3px คงไว้ (ข) ขนาดที่ต้องขยายตามตัวอักษร (ความสูงปุ่ม, ไอคอน, มาสคอต, แท่งกราฟ) → แปลงเป็น rem (ค) ค่าที่ซ้ำกับ token → ใช้ token
3. **ไม่รีเซ็ตผู้ใช้เดิม:** ผู้ที่เคยกดเลือกขนาดมี key เดิมอยู่ → ขนาดที่เห็น (px) ต้องคงอยู่ ผู้ที่ไม่เคยกดจะได้ ก = 16px ตามเจตนา การย้ายค่า (ครั้งเดียว, เก็บใน key ใหม่ `yatung_font_scale_v2`, ไม่ลบ key เดิม):

| ค่าเดิมที่เลือกไว้ | px เดิม | → ขนาดใหม่ | px ใหม่ |
|---|---|---|---|
| 100 (ก) | 18 | ก+ | 18 ตรงเป๊ะ |
| 112 (ก+) | 20.2 | ก++ | 20 ใกล้เคียง |
| 125 (ก++) | 22.5 | ก++ | 20 เล็กลง 11% |

   inline script ใน `index.html` และ `FontScaleService.load()` ทำ migration เดียวกัน; unit test ครบ 3 แถว + ไม่มี key + storage ถูกบล็อก → **คำถาม Q1** (แถว 125)
4. กฎใน CLAUDE.md "ตัวหนังสือ ≥ 18px, ปุ่มสูง ≥ 56px" จะถูกแทนด้วย "ก = 16/48px, ก+ = 18/54px, ก++ = 20/60px" (ปุ่ม = `3rem`) ตอนจบ D1 — **ต้องแก้ CLAUDE.md ด้วย**
5. Ionic (หน้า Scan) ใช้ px ในบางคอมโพเนนต์ → override ใน `_ionic.scss` ให้ตาม token; หน้า Scan ใช้ `yt-page-header` แทน `ion-header` (ยังใช้ `ion-toast`/ปุ่ม Ionic ตามเดิม)

### 2.5 endpoint "กินครบมื้อนี้" (คำตอบข้อ 3)

- **มีอะไรอยู่แล้ว:** `doseService.takeMany(db, userId, ids, source, opts)` — transaction เดียว, ข้าม id ที่ไม่ใช่ของผู้ใช้ (นับ `skipped`), id ที่กินแล้วนับ `already` (ไม่หักสต็อกซ้ำ), ใช้ `takeInTx` ตัวเดียวกับ `take()`, เรียก hook ปิดเรื่องญาติหลัง COMMIT — **แต่ยังไม่มี HTTP endpoint** (ใช้ผ่าน LINE postback / push token เท่านั้น)
- **ข้อเสนอ: เพิ่ม `POST /api/doses/take-many`** (tab 4-Doses, JWT, group เขียว ตามกฎจัด flow)
  - body `{ ids: number[] }` (1–50 จำนวนเต็มบวก; ผิด = 400 `VALIDATION` ข้อความไทย)
  - เรียก `takeMany(db, msg.user.id, ids, 'app')` → `200 { taken: [id], already: [id], skipped: n, at: "HH:MM" }`
  - ไม่มี id ไหนเป็นของผู้ใช้เลย (taken+already ว่างและ skipped > 0) → `404 NOT_FOUND` ตามกฎ "ไม่ใช่ของ msg.user.id = 404 เสมอ" ; ผสม = 200 พร้อม `skipped` (ไม่เผยว่าของใคร)
  - ปุ่มในแอปส่งเฉพาะ id ที่ยังไม่กินของมื้อนั้น แล้ว reload `GET /api/doses/today`
  - ทางเลือกที่ไม่แนะนำ: เรียก `take` ทีละตัว — ไม่ atomic (เน็ตหลุดกลางทางได้ครึ่งเดียว), n requests, hook ปิดเรื่องยิงหลายรอบ
  - เทสใหม่: `node --test` (ตรวจ ids) + `scripts/test-day8d.sh` (ต้องใช้ docker — **ถามก่อนรัน**): เจ้าของ / ผู้ใช้อื่น = 404 / ผสม = skipped / กดซ้ำ = already ไม่หักซ้ำ / `remaining_qty` ลดถูก / source = `app` / ids ว่าง-ผิดรูป = 400 / ไม่มี JWT = 401

### 2.13 วิธีคีย์บอร์ดบนมือถือ (Login/Register)

- Android Chrome: เพิ่ม `interactive-widget=resizes-content` ใน meta viewport ของ `index.html` (ทำให้ layout viewport หดตามคีย์บอร์ด ปุ่มยืนยันขยับขึ้นมาเอง) — ใช้ทั้งแอป ต้องเช็กว่าไม่กระทบแถบเมนูล่าง/ปุ่ม sticky หน้าอื่น
- iOS Safari ไม่รองรับค่านี้: ฟอร์ม auth เป็น scroll container อยู่แล้ว → ตอน `focusin` ของช่องกรอก เรียก `scrollIntoView({ block: 'center' })` ของ**ช่องและปุ่มยืนยันรวมกัน** (ใช้ wrapper ของส่วนล่างฟอร์มเป็นเป้า) หลังหน่วง ~300ms ให้คีย์บอร์ดเปิด ; padding ล่างของฟอร์มเผื่อคีย์บอร์ด (`env(keyboard-inset-height)` ถ้ามี)
- ตรวจได้เฉพาะกลไก (viewport + scroll) ด้วย Playwright ; **พฤติกรรมคีย์บอร์ดจริงต้องทดสอบบนเครื่องจริง** (เพิ่มลง `docs/day8-device-checklist.md`)

#### ช่วง 1 — สเปก /medications (384 ก)
1. หัวหน้า "ยาของฉัน" + ปุ่ม "＋ เพิ่มยา" (แบบเดิม)
2. น้องยาตรง S + กล่องคำพูด 1 กล่อง (คอมโพเนนต์เดียวกับหน้าสแกน): ใกล้หมด 1 ตัว (warning) "{ชื่อ} ใกล้หมดแล้วนะคะ เหลือพอใช้อีก {n}&nbsp;วันค่ะ" · หลายตัว (warning) "{ชื่อตัวที่หมดก่อน} กับอีก {n} ตัวใกล้หมดแล้วนะคะ" · พอใช้ทุกตัว (success) "ยาทุกตัวพอใช้ค่ะ เก่งมากเลยนะคะ" · แท็บหยุดแล้ว (neutral) "ยาที่หยุดแล้ว กดกลับมาใช้ได้นะคะ" · ยังไม่มียา (info) "ยังไม่มียาเลยค่ะ ลองสแกนซองยาดูนะคะ" + ปุ่มสแกน
3. segment กำลังใช้/หยุดแล้ว (fitLabel แบบกลุ่ม)
4. การ์ด: หัว ชื่อ(หนา)+ความแรง(สีรอง) + ขวา ป้าย "ใกล้หมด" หรือ › (ชื่อตัดบรรทัดได้ ป้ายอยู่ขวาบนเสมอ) → วิธีกิน → ชิปมื้อสีมื้อ → ข้อบ่งใช้ (สีรอง) → แถบคงเหลือ (ใกล้หมดพื้นส้มอ่อน) → [＋ เติมยา] [✎ แก้ไข] (เติมยาทึบเฉพาะตัวใกล้หมด ตัวอื่น tonal) ; การ์ดใกล้หมดขอบส้มเหมือนเดิม
5. ลบ ⋮ ; แตะการ์ด (ยกเว้นปุ่ม) → sheet รายละเอียด: หัว, ตาราง วิธีกิน/มื้อ/ใช้สำหรับ/คงเหลือ, [เติมยา][แก้ไข], ปุ่มข้อความ "หยุดใช้ยานี้" → ยืนยัน inline ; การ์ด role=button Enter/Space ; sheet ปิดด้วยปัด/ปุ่มย้อนกลับ/Esc
6. ไม่เลื่อนแนวนอนทุกความกว้าง
