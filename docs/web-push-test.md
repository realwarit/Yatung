# ทดสอบ Web Push (แจ้งเตือนบนเครื่อง) บนมือถือจริง — 7C

แบ่งเป็น **2 ชุด** ทำแยกกันได้: **ชุด A = iPhone** · **ชุด B = Android (Chrome)**
ผลที่ต้องรายงานกลับ: ติ๊กผ่าน/ไม่ผ่านทีละข้อ + ถ้าไม่ผ่านให้แนบ `docker compose logs nodered --since 10m | grep -E "web_push|push"` (log ไม่มีคีย์/JWT/ชื่อยา)

## ก่อนเริ่ม (ทำครั้งเดียวบนคอมพิวเตอร์)

1. สร้างคีย์ VAPID (ถ้ายังไม่เคย — สคริปต์ไม่เขียนทับคีย์เดิม):
   ```bash
   node scripts/gen-vapid.mjs
   ```
2. ตั้ง `VAPID_SUBJECT` ใน `.env` เป็น `mailto:<อีเมลของคุณ>` (เช่น `mailto:me@yatung.example`) — ถ้า iPhone ไม่ได้รับ ดู "ถ้า Apple ปฏิเสธ" ท้ายเอกสาร
3. โหลดคีย์และหน้าเว็บใหม่:
   ```bash
   docker compose up -d --build frontend
   docker compose up -d --force-recreate nodered
   docker compose --profile tunnel up -d
   bash scripts/demo-check.sh
   ```
   `demo-check.sh` ต้องผ่านข้อ **Web Push** (VAPID ครบ, `ngsw-worker.js` และ `manifest.webmanifest` ผ่าน tunnel ได้ไฟล์จริง ไม่ใช่หน้าเตือนของ ngrok)
4. **ต้องเปิดผ่านลิงก์ https ของ tunnel** (`https://<NGROK_DOMAIN>`) ไม่ใช่ `localhost:8080` — มือถือรับแจ้งเตือนจากเว็บ http ไม่ได้
5. ngrok ฟรีแสดงหน้า "You are about to visit…" ตอนเปิดครั้งแรก กด **Visit Site** (เจอซ้ำอีกครั้งตอนเปิดแอปจากหน้าจอโฮมบน iPhone เพราะ cookie แยกจาก Safari)
6. เตรียมบัญชีทดสอบ **ที่ไม่ได้เชื่อม LINE** (กฎ: เชื่อม LINE แล้ว = ส่ง LINE ทางเดียว; ยังไม่เชื่อมแต่เปิดแจ้งเตือนบนเครื่อง = ส่ง Web Push; เปิดสวิตช์ "ส่งทั้ง LINE และแจ้งเตือนบนเครื่อง" = ทั้งสองทาง)
   — ใช้ปุ่ม "ยกเลิกการเชื่อม" ในหน้าตั้งค่าชั่วคราวได้ แล้วเชื่อมกลับทีหลัง

ตัวช่วยตอนทดสอบเตือนจริง: ในหน้าตั้งค่าตั้งเวลามื้อให้ **อีก 2–3 นาที** แล้วเพิ่มยา 1 ตัวในมื้อนั้น (หรือแก้เวลามื้อที่มียาอยู่) — cron เช็กทุก 1 นาที

## ชุด A — iPhone (iOS 16.4 ขึ้นไป, Safari)

> iPhone รับ Web Push ได้เฉพาะแอปที่ **เพิ่มลงหน้าจอโฮมแล้ว** · notification บน iOS **ไม่มีปุ่ม "✓ กินแล้ว"** (แตะตัวแจ้งเตือนเพื่อเปิดแอปแล้วกดในหน้าวันนี้)

| # | ขั้นตอน | ผลที่ควรเห็น | ผ่าน? |
|---|---|---|---|
| A1 | เปิด `https://<NGROK_DOMAIN>` ด้วย **Safari** → Visit Site → เข้าสู่ระบบ | หน้าวันนี้ขึ้นปกติ | ☐ |
| A2 | ไป **ตั้งค่า → แจ้งเตือนบนเครื่องนี้** | ขึ้นข้อความ "ต้องเพิ่มแอปลงหน้าจอโฮมก่อน" พร้อมวิธี ①②③ มีไอคอนปุ่มแชร์ **ยังไม่มีปุ่ม "เปิดการแจ้งเตือน"** | ☐ |
| A3 | แตะปุ่ม **แชร์** (แถบล่างของ Safari) → เลื่อนลง **เพิ่มลงหน้าจอโฮม** → เพิ่ม | มีไอคอน "ยาตรง" บนหน้าจอโฮม | ☐ |
| A4 | ปิด Safari แล้วเปิดแอปจาก **ไอคอนบนหน้าจอโฮม** (ถ้าเจอหน้า ngrok กด Visit Site, และต้องเข้าสู่ระบบใหม่ เพราะที่เก็บข้อมูลแยกจาก Safari) | แอปเปิดเต็มจอไม่มีแถบ Safari | ☐ |
| A5 | ตั้งค่า → แจ้งเตือนบนเครื่องนี้ | ขึ้นปุ่ม **เปิดการแจ้งเตือน** (สถานะ "ยังไม่เปิด") | ☐ |
| A6 | แตะ **เปิดการแจ้งเตือน** → ระบบถามสิทธิ์ → **อนุญาต** | ขึ้น "เปิดการแจ้งเตือนบนเครื่องนี้แล้ว" + ปุ่มทดลอง/ปิด | ☐ |
| A7 | แตะ **ทดลองส่งแจ้งเตือน** (ล็อกหน้าจอไว้ได้) | ภายใน ~10 วินาที ได้แจ้งเตือน "🔔 ทดลองแจ้งเตือนจากยาตรง" · แตะแล้วเปิดแอปที่หน้าตั้งค่า | ☐ |
| A8 | ตั้งเวลามื้อให้อีก 2–3 นาที + มียาในมื้อนั้น (บัญชีที่ **ไม่ได้เชื่อม LINE**) แล้วรอ | ได้แจ้งเตือน "⏰ ถึงเวลากินยามื้อ… แล้ว" เนื้อหา "n รายการ · แตะเพื่อดูและบันทึก" **ไม่มีชื่อยา** (ตรวจบนหน้าจอล็อก) | ☐ |
| A9 | แตะแจ้งเตือน | เปิดแอปที่หน้า **วันนี้** · กดปุ่ม "กินแล้ว" ในแอป → บันทึกได้ | ☐ |
| A10 | ตั้งค่า → ปิดการแจ้งเตือนบนเครื่องนี้ → ทดลองส่ง | หลังปิด ปุ่มทดลองหายไป · เปิดใหม่ได้ | ☐ |
| A11 | (ถ้าเชื่อม LINE อยู่) เปิดสวิตช์ **ส่งทั้ง LINE และแจ้งเตือนบนเครื่อง** แล้วรอรอบเตือนถัดไป | ได้ทั้ง LINE และแจ้งเตือนบนเครื่อง **อย่างละ 1 ครั้ง** (ไม่ซ้ำ) | ☐ |

ตรวจฝั่งเซิร์ฟเวอร์หลัง A7/A8 (Adminer หรือ mysql):
```sql
SELECT sent_at, kind, success, error_message FROM notification_logs WHERE channel='web_push' ORDER BY id DESC LIMIT 5;
SELECT id, last_success_at, fail_count FROM push_subscriptions;   -- fail_count ต้อง 0
```

### ถ้า Apple ปฏิเสธ (ไม่มีแจ้งเตือน + log เป็น `status=403 reason=BadJwtToken`)
Apple เข้มกับ `VAPID_SUBJECT` — แก้ใน `.env` ให้เป็น `https://<NGROK_DOMAIN>` (หรือ mailto ที่เป็นอีเมลจริงของคุณ) แล้ว
```bash
docker compose up -d --force-recreate nodered
```
จากนั้นบน iPhone: ตั้งค่า → **ปิดการแจ้งเตือน** แล้ว **เปิดใหม่** (สร้าง subscription ใหม่) ลองทดลองส่งอีกครั้ง

## ชุด B — Android (Chrome)

> Android Chrome รองรับ **ปุ่ม action "✓ กินแล้ว"** บนแจ้งเตือน (กดแล้วแอปเปิดที่ `/today?take=…` และบันทึกให้เอง)

| # | ขั้นตอน | ผลที่ควรเห็น | ผ่าน? |
|---|---|---|---|
| B1 | เปิด `https://<NGROK_DOMAIN>` ด้วย **Chrome** → Visit Site → เข้าสู่ระบบ (ติดตั้งเป็นแอป "เพิ่มลงหน้าจอหลัก" ก็ได้ ไม่บังคับ) | หน้าวันนี้ขึ้นปกติ | ☐ |
| B2 | ตั้งค่า → แจ้งเตือนบนเครื่องนี้ | สถานะ "ยังไม่เปิด" + ปุ่ม **เปิดการแจ้งเตือน** | ☐ |
| B3 | แตะ **เปิดการแจ้งเตือน** → อนุญาต | "เปิดการแจ้งเตือนบนเครื่องนี้แล้ว" | ☐ |
| B4 | แตะ **ทดลองส่งแจ้งเตือน** | แจ้งเตือน "🔔 ทดลองแจ้งเตือนจากยาตรง" ภายในไม่กี่วินาที · แตะแล้วเปิดตั้งค่า | ☐ |
| B5 | ตั้งเวลามื้อให้อีก 2–3 นาที (บัญชีที่ไม่ได้เชื่อม LINE) แล้วรอ | แจ้งเตือน "⏰ ถึงเวลากินยามื้อ… แล้ว" มีปุ่ม **✓ กินแล้ว** · เนื้อหาไม่มีชื่อยา · เครื่องสั่น/ค้างจนกว่าจะปิด | ☐ |
| B6 | กดปุ่ม **✓ กินแล้ว** บนแจ้งเตือน | แอปเปิดหน้าวันนี้ มีแถบ "บันทึกแล้วค่ะ ✓ กินยา N รายการ" · การ์ดยาเป็น "กินแล้ว" · ข้อความใต้การ์ด "จากการแจ้งเตือนบนเครื่อง" · ที่อยู่เว็บไม่มี `?take=` ค้าง | ☐ |
| B7 | รีเฟรชหน้าทันที | **ไม่** บันทึกซ้ำ ยาไม่ถูกหักซ้ำ (จำนวนยาคงเหลือลดแค่ 1 ครั้ง) | ☐ |
| B8 | รอบถัดไป: แตะ **ตัวแจ้งเตือน** (ไม่ใช่ปุ่ม) | เปิดหน้าวันนี้เฉยๆ ยัง **ไม่** บันทึกว่ากิน | ☐ |
| B9 | ปิดแอปไว้ (ไม่ได้เปิดค้าง) แล้วกดปุ่ม ✓ จากแจ้งเตือนที่ค้างอยู่ | แอปเปิดขึ้นมาแล้วบันทึกได้ (ถ้ายังไม่ได้เข้าสู่ระบบก็บันทึกได้ — ปุ่มใช้ token ของแจ้งเตือน อายุ 12 ชม.) | ☐ |
| B10 | ตั้งค่าไซต์ใน Chrome → การแจ้งเตือน → **บล็อก** แล้วกลับมาหน้าตั้งค่า กด "ตรวจสอบอีกครั้ง" | สถานะ "ถูกบล็อก" พร้อมวิธีเปิด (Android: ไอคอนข้างชื่อเว็บ → การอนุญาต) | ☐ |
| B11 | ออกจากระบบ แล้วเข้าสู่ระบบด้วย **บัญชีอื่น** บนเครื่องเดิม → เปิดหน้าตั้งค่า | เครื่องนี้ย้ายเป็นของบัญชีใหม่ (บัญชีเดิมไม่ได้แจ้งเตือนซ้ำ) | ☐ |
| B12 | (ถ้าเชื่อม LINE อยู่) สวิตช์ **ส่งทั้ง LINE และแจ้งเตือนบนเครื่อง** | เปิด = ได้ทั้งสองทางอย่างละ 1 ครั้ง · ปิด = LINE ทางเดียว | ☐ |

## ข้อสังเกตที่ควรจดระหว่างทดสอบ
- แจ้งเตือนมาช้ากว่า ~1 นาทีหลังเวลามื้อหรือไม่ (cron เช็กทุก 1 นาที; iOS/Android อาจหน่วงเมื่อประหยัดแบตเตอรี่)
- ตัวหนังสือบนหน้าตั้งค่า/แจ้งเตือนอ่านง่ายที่ ก+ / ก++ หรือไม่ ปุ่มกดง่ายหรือไม่
- ถ้าเปิดแอปจากหน้าจอโฮมบน iPhone แล้วเจอหน้า ngrok ซ้ำทุกครั้ง ให้บอก (ทางแก้ในแผน: header `ngrok-skip-browser-warning` / ย้ายไป Cloudflare Tunnel)
