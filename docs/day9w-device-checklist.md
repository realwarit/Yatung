# ชุด 7 — หน้าต้อนรับ บน Samsung Galaxy S23 FE (วันที่ 9W)

## ผลทดสอบ — **ผ่านครบทุกข้อ (7-1 ถึง 7-18)**
- วันที่ทดสอบ: 17 ต.ค. 2569 (2026-10-17)
- เครื่อง: Samsung Galaxy S23 FE (SM-S711B) · One UI 8.5 / Android 16
- build ที่ทดสอบ: apk จาก `d9fa3a4` (cap sync หลัง commit fix) · ข้อ 7-16 ใน Chrome Incognito · ไม่มีการออกจากระบบบน PWA/Chrome ปกติ
- สรุปรายข้อ: A 7-1/7-2/7-3 ผ่าน · B 7-4/7-5/7-6/7-7 ผ่าน · C 7-8/7-9/7-10/7-11 ผ่าน · D 7-12/7-13/7-14/7-15/7-16 ผ่าน · E 7-17/7-18 ผ่าน


ตัวแอปซิงก์เข้า `frontend/android` แล้ว (`npm run cap:sync` ผ่านเมื่อ 17 ต.ค.) ที่ CLI ไม่มี JDK 21 จึง **build apk ใน Android Studio ตาม [`docs/day9-android.md`](day9-android.md)** (Gradle JDK = 21, ห้ามกด Upgrade AGP) → ต่อ USB → Run ; ถ้าเคยติดตั้งไว้ ให้ถอนการติดตั้งแอปเก่าก่อน (ล้าง state)

**ข้อควรระวัง (PWA บัญชี "การ์ตูน" ถือ Web Push):** ทุกข้อที่ต้องออกจากระบบ ให้ทำบน **apk เท่านั้น** (storage ของ apk แยกจาก PWA/Chrome) ห้ามออกจากระบบบน PWA หรือ Chrome ปกติ (Chrome กับ PWA ที่ origin เดียวกันใช้ localStorage ร่วมกัน — ออกจากระบบฝั่งไหนก็หลุดทั้งคู่) ; ข้อ 7-16 ใช้ Incognito แทน

ข้อ 7-1 ถึง 7-15 และ 7-17/7-18 ทดสอบบน **apk** ; ข้อ 7-16 ใช้ Chrome Incognito ; PWA ที่ติดตั้งแล้วไม่ต้องทำอะไรในชุดนี้

ถ่ายภาพ/วิดีโอสั้นตามเลขจุด แล้วบอกผลเป็นข้อๆ (ผ่าน/ไม่ผ่าน + ข้อสังเกต)

## A. เปิดแอป (cold start)
| จุด | ทำ | ต้องเห็น |
|---|---|---|
| 7-1 | ตั้งค่า → แอป → ยาตรง → **บังคับหยุด** แล้วแตะไอคอน (ยังไม่ล็อกอิน: ถ้าเคยล็อกอินให้ออกจากระบบก่อนแล้วบังคับหยุด) | splash มิ้นต์จังหวะเดียว → **หน้าต้อนรับ** ไม่มีจอขาวแวบ |
| 7-2 | ดูฉากเปิดตั้งแต่เริ่ม (อัดวิดีโอ ~5 วินาที) | ฟ้าสว่าง → ดวงอาทิตย์ขึ้น → เนินเลื่อนขึ้น → น้องยาตรงกระโดดลงยุบเด้ง → ตัวอักษร "ยาตรง" หล่นทีละตัว → กล่องคำพูด "สวัสดีค่ะ!" → คำโปรย → ปุ่ม |
| 7-3 | ตอนฉากยังเล่น (ภายใน 1 วินาทีแรก) ลองแตะ "เริ่มต้นใช้งาน" | ปุ่มกดได้ทันที พาไปหน้า login |

## D. ล็อกอินและ deep link
| จุด | ทำ | ต้องเห็น |
|---|---|---|
| 7-12 | ต้อนรับ → เริ่มต้น → ล็อกอิน (บัญชีเดโม) | เข้า `/today` (ไม่ย้อนผ่านหน้าต้อนรับ) |
| 7-13 | ล็อกอินค้างอยู่ → บังคับหยุด → เปิดใหม่ | เข้า `/today` ตรง **ไม่เห็นหน้าต้อนรับ** (ไม่กะพริบหน้าต้อนรับก่อน) |
| 7-14 | ในหน้าวันนี้ กด back | ออกแอป (หน้าต้อนรับไม่ค้างในประวัติ) |
| 7-15 | ออกจากระบบ (ตั้งค่า) | ไปหน้า login (ไม่ใช่ต้อนรับ — เป็นพฤติกรรมเดิม) |
| 7-16 | **deep link (ทดสอบใน Chrome แท็บไม่ระบุตัวตน/Incognito เท่านั้น — ห้ามออกจากระบบบน PWA/Chrome ปกติ)** เปิดแท็บ Incognito → วางลิงก์ `<โดเมน tunnel>/today` (ถ้าเจอหน้าเตือน ngrok กด Visit Site) | ไปหน้า login (`?returnUrl=/today`) หลังล็อกอินกลับ `/today` — **ไม่ผ่านหน้าต้อนรับ** ; แล้วเปิด `<โดเมน>/` ใน Incognito เดิม (ก่อนล็อกอิน) ต้องได้หน้าต้อนรับ (ภาพ URL bar) |

## E. ลดภาพเคลื่อนไหว
| จุด | ทำ | ต้องเห็น |
|---|---|---|
| 7-17 | ตั้งค่า Android → การเข้าถึง → ปรับปรุงการมองเห็น → **ลบเอฟเฟกต์ภาพเคลื่อนไหว** (Remove animations) เปิด → เปิดแอปใหม่ (cold start) | หน้าต้อนรับขึ้นเป็นภาพนิ่งครบทุกชิ้นในท่าสุดท้าย (ไม่มีชิ้นที่หายไป ยกเว้นนกและประกายที่ซ่อน) ปุ่มกดได้ |
| 7-18 | ปิดตัวเลือกข้างบนกลับ | ฉากเคลื่อนไหวกลับมา |

หมายเหตุเรื่อง PWA ที่ติดตั้งไว้แล้ว (WebAPK):
- ใน Chrome เปิด `/` ตอนยังไม่ล็อกอินต้องได้หน้าต้อนรับ
- `start_url` ที่ไอคอนบนหน้าจอใช้ **ถูกเก็บในตัว WebAPK** และเปลี่ยนเมื่อ **Chrome ตรวจอัปเดต WebAPK เอง** (กลไกของ Chrome ตรวจเป็นรอบ ไม่ใช่ทุกครั้งที่เปิด) — **ไม่ได้เปลี่ยนตอน service worker อัปเดตแอป** (เวอร์ชันที่เขียนไว้ก่อนหน้านี้ผิด) ตัวอัปเดตของ service worker กับของ WebAPK เป็นคนละกลไกกัน
- manifest เคยเป็น `start_url` `/today` ระหว่าง 13–17 ต.ค. (commit `aa3cf6f` ถึง `6de8580`) ไอคอนที่ติดตั้งหรือถูก Chrome อัปเดตในช่วงนี้จะเปิดที่ `/today` → ยังไม่ล็อกอินจึงไป `/login` **จนกว่า Chrome จะอัปเดต WebAPK เป็น `start_url` `/`** ตามกฎ deep link (ลิงก์ลึกไม่ผ่านหน้าต้อนรับ) — ไม่ใช่บั๊ก
- **ยืนยันบนเครื่องจริง (17 ต.ค. 2569, Samsung Galaxy S23 FE SM-S711B):** `chrome://webapks` แสดง Manifest Start URL ของยาตรง = `/today` โดย Last Update Check = 11:55 (ก่อน deploy เวอร์ชันใหม่ที่ `start_url` = `/`) → สาเหตุที่ PWA เปิดแล้วไป `/login` ไม่ใช่ `/welcome` คือ WebAPK ยังถือ `start_url` เดิม (สมมติฐาน H-B) ไม่ใช่ service worker ค้างเวอร์ชันเก่า และไม่ใช่บั๊กของหน้าต้อนรับ ; ค่าใหม่จะเข้าเมื่อ Chrome ตรวจอัปเดต WebAPK รอบถัดไป
- ตรวจ `start_url` ที่ WebAPK ถืออยู่แบบไม่ต้องออกจากระบบ/ถอนการติดตั้ง: `chrome://webapks` ; ตรวจเวอร์ชันที่ service worker เสิร์ฟ: เปิด `<โดเมน>/welcome` ใน Chrome ปกติ (เห็นหน้าต้อนรับ = service worker เป็นเวอร์ชันใหม่แล้ว) หรือ `<โดเมน>/ngsw/state`
- ถ้าอยากเห็นหน้าต้อนรับบน PWA ทันที ต้องถอนการติดตั้งแล้วติดตั้งใหม่ — **ห้ามทำกับ PWA ของบัญชี "การ์ตูน" (ถือ Web Push)**
