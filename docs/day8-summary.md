### 8A — Dashboard
- `GET /api/stats/adherence?days=7` (JWT, no-store): นิยามเดียวทั้งระบบ (API / เว็บ `/overview` / LINE "สรุป") — `due = taken + missed + pending_due`, `rate = round(taken×100/due)`, `due=0 → null` · เวลาไทยคำนวณใน JS ส่งเข้า SQL เป็นพารามิเตอร์ (ไม่ใช้ `NOW()`)
- หน้า "สรุป 7 วัน" 2 การ์ด (วงแหวน + แท่งรายวัน / แยกตามยา) สเกลสีเดียว `toneOf`, วันนี้ที่ยังไม่จบแสดง "n/ทั้งหมด" ไม่ใช่ 0% · LINE "สรุป" สำหรับผู้ป่วยและผู้ดูแล (ไม่มีชื่อยาในฝั่งผู้ดูแล)

### 8B — อ่านออกเสียง
- Web Speech API ฝั่งเบราว์เซอร์ล้วน ไม่ส่งข้อความไปที่ใด · ไม่มี auto-play · `speak()` ต้องเรียกแบบ synchronous จากการแตะ · ปุ่ม 🔊 ตัวเดียวทั้งแอป · ตั้งค่าเสียง/ความเร็วต่ออุปกรณ์

### 8C — PWA / ออฟไลน์ / แก้จากเครื่องจริง
- **C0:** iPhone ค้างเพราะหน้าเตือน ngrok (HTML สถานะ 200) → header ข้ามหน้าเตือน, ตัวตรวจจับ HTML, แถบ "การเชื่อมต่อหมดอายุ" แตะกู้กลับได้ (ผ่านบนเครื่องจริง)
- **C1–C3:** manifest ครบ, เลิกโหลดอะไรจาก CDN, ออฟไลน์อ่านอย่างเดียว (snapshot whitelist, ล้างตอน logout), แจ้งอัปเดตเวอร์ชัน, การ์ดชวนติดตั้ง (Android prompt / iPhone สอน)
- **C5:** ชื่อยาตัวพิมพ์ใหญ่ล้วนอ่านเป็นตัวเล็ก
- **C6 (จากเครื่องจริง):**
  - `/api/*` ตอบ `Cache-Control: private, no-store` และไม่ตอบ 304 (`lib/api-headers.js`) — เดิมมี ETag ไม่มี Cache-Control ทำให้ iPhone เก็บข้อมูลสุขภาพในแคช
  - รหัสอ้างอิง error `(E-304 | E-NET | E-HTML | E-401 | E-5xx | E-JS)`, บันทึก error 20 รายการในเครื่อง (ส่วน "ข้อมูลสำหรับผู้พัฒนา" เฉพาะ `demoMode`), log 500 ลง `node-red/data/logs/errors.log` (หมุน 1 MB × 3), `apple-touch-icon` ที่ root
  - TTS: พจนานุกรมคำอ่านไทย `core/tts/tts-lexicon.ts` (เว้นวรรคระหว่างพยางค์), `lang = th-TH` เสมอ, `canSpeak` ไม่รอรายการเสียง, แสดงเสียงที่ใช้ในตั้งค่า, คำแนะนำใต้ช่องชื่อที่ให้อ่านออกเสียง
- ฟอนต์: import เฉพาะ subset thai+latin — woff2 ที่ดึงสูงสุด 255 → 164 kB

## บทเรียน
- **เสียงไทยของ iOS ตัดคำทับศัพท์ผิด** (เช่น "วิตามิน" → "วิ-ตาม-อิ-นอ") แก้ด้วยการเว้นวรรคระหว่างพยางค์ ("วิ ตา มิน") ทั้งในพจนานุกรมและคำแนะนำให้ผู้ใช้ที่ตั้ง `tts_name` เอง — ยืนยันบน iPhone จริง
- **ngrok ฟรี + iOS:** หน้าเตือน (HTML สถานะ 200) ทำให้แอปบนหน้าจอโฮมค้าง เพราะคุกกี้แยกจาก Safari และ service worker เสิร์ฟจากแคช → ต้องมีแถบกู้กลับ และตรวจ content-type ของ API เสมอ
- **API ที่มี ETag แต่ไม่มี Cache-Control** ถูกเบราว์เซอร์เก็บและยิงตรวจซ้ำเป็น 304 ซึ่ง Angular `HttpClient` นับเป็น error (อาการ "เกิดข้อผิดพลาด" เป็นระยะบน iPhone) → ข้อมูลสุขภาพต้อง `no-store` เสมอ ; ยังพิสูจน์ไม่ได้ว่า 304 คือต้นเหตุเดียว จึงเพิ่มรหัสอ้างอิง + บันทึก error ไว้ยืนยันรอบหน้า
- **หลักฐานต้องเก็บก่อน recreate:** log ของ nodered หายเมื่อ recreate (ช่วงที่คาเด็ททดสอบหายไป) → เขียน `errors.log` ลงไฟล์ที่ bind mount · ngrok inspector เก็บย้อนหลังได้จำกัด ควรดึงก่อน
- **ตรวจข้อมูลก่อนเดาโค้ด:** "tts_name ไม่ถูกใช้" จริงๆ คือไม่เคยถูกบันทึก (ngrok ไม่มี PUT, DB เป็น NULL) ไม่ใช่บั๊กในโค้ดพูด
- **ดูภาพจริงเสมอ:** การ์ดชวนติดตั้งไม่มี padding และชิปล้นที่ 320px ก++ — ผ่านเทสอัตโนมัติแต่เห็นได้จากภาพที่ถ่ายด้วย `state-check.mjs` · ทุกงาน UI ต้องวัดที่ 360px
- **เทสที่อ่านการตั้งค่าจริง** (angular.json) พังเมื่อเปลี่ยนรูปแบบ import ฟอนต์ — เทสแบบนี้ควรตรวจเจตนา (ใช้ฟอนต์ครบ) ไม่ใช่รูปแบบของไฟล์
- **real-snapshot 3 ระดับ:** cron จริงเปลี่ยนข้อมูลผู้ใช้จริงได้ตามปกติ (เตือน, แจ้งญาติ) จึงแยก ⓘ ออกจาก ✘ แทนการปิด cron ระหว่างเทส
